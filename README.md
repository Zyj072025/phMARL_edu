# Ph-MARL-Edu —— 领域知识个性化生成与多智能体协同决策系统

**揭榜挂帅赛题 XH-202630**（上海云之脑智能科技有限公司）

把多智能体强化学习中的两个核心机制 —— **安全约束投影（CBF-QP）** 与 **因果门控通信（I2C）** ——
转译到"领域知识个性化生成"与"多智能体协同决策"上，做成一套**零第三方依赖**、
**可离线复现**、**每条结论都可溯源**的学习资源生成系统。

> 一句话：**资源不是"生成完就发"，而是"生成 → 逐条取证 → 冲突必处置 → 再交付"。**

## 二、快速开始

零第三方依赖，纯 Python 标准库（自带 BM25 检索、Levenshtein、`http.server` 界面、
`urllib` 调用 OpenAI 兼容接口）。要求 Python 3.8+。

```bash
# 1) 跑通一个画像的完整闭环（默认 mock 后端，离线、确定性）
python run.py --profile L001

# 2) 三组画像全跑
python run.py --all-profiles

# 3) 浏览器界面（内置 http.server，无需 Flask）
python run.py --ui --port 8017

# 4) 接真实大模型（OpenAI 兼容接口）
set PHMARL_LLM_API_KEY=sk-xxx          # Windows PowerShell: $env:PHMARL_LLM_API_KEY="sk-xxx"
set PHMARL_LLM_BASE_URL=https://api.openai.com/v1
set PHMARL_LLM_MODEL=gpt-4o-mini
python run.py --profile L001 --backend openai

# 5) 五组消融评测 + τ 扫描
python eval/run_eval.py

# 6) 适配率上界检验（oracle ceiling）
python eval/oracle_ceiling.py

# 7) 单元测试（171 条）
python -m unittest discover -s tests
```

产物落在 `out/<画像ID>/`：

| 文件 | 内容 |
|---|---|
| `resources.md` | 本轮交付的全部资源（讲义/指南/题），每条处置过的声明在文末附录里逐条列明"改了什么、为什么" |
| `audit_trace.json` | 审核明细：每条声明的检索证据（doc_id + 章节）、三态判定、判定理由 |
| `report.json` / `report.html` | 匹配度报告：盲区定位、难度匹配曲线、路径规划、指标汇总 |
| `session.json` / `trace.jsonl` | 完整会话与可审计事件流（多智能体之间每条消息的**发送/抑制及理由**） |

## 三、两个核心创新（形式化同构，不是类比）

### 创新点一：知识约束投影（Knowledge-Constrained Projection）

前期科研中的安全投影：

```
min_u ‖u − u_raw‖²     s.t.  A·u ≤ b      （即 h(x) ≥ 0，CBF 约束）
```

转译到知识生成：

```
min_{x′} EditDistance(x′, x_raw)     s.t.  每条声明 ∈ {SUPPORTED}
```

**在"每条结论都能溯源"的许可集内，找与原始生成编辑距离最小的改写**。工程上分三步，
每步都可审计（`engine/projection.py`）：

1. **候选生成**：对每条判为冲突的声明生成 `REPLACE`（最小改写）/ `LIMIT`（限定化）/ `DELETE`（删除并显式标注）；
2. **可行性判定（关键）**：候选必须**再审核一次**，复审不再冲突才算可行 —— 修正是**被验证过的**，不是"再生成一次赌它对"；
3. **最小改动选择**：在可行候选中取编辑距离最小者。删除的代价记为该声明整体（= 1.0），因此删除天然是"最后手段"。

`engine/llm.py` 的 `jaccard` 相似度用于"这条声明是不是某条已知误区的另一种说法"，
`engine/projection.py::subject_overlap` 用于防止改写**换掉题目**（把"确认 Python 版本"
改成"折扣因子取值"这种主体漂移会被拒绝）。

### 创新点二：门控通信（I2C → 消息必要性判据）

I2C 用**因果影响**判断"一个智能体的动作是否值得告知另一个"；本系统用同一判据决定
**Agent 之间的消息是否值得发送**：`impact_of(kind, ctx)` 估计该条消息对下游决策的影响，
`τ` 以下的消息被抑制但**仍记录理由**（`engine/gating.py`）。收益用两个指标衡量：
**通信稀疏度**（发送/候选）与 **token 节省率**。消融中 D 组相对 C 组把稀疏度降到 83.3%、
token 节省 31.0%，而幻觉率与适配率**没有任何退化**。

## 四、评测结果（`python eval/run_eval.py`，mock 后端，3 画像 × 3 轮 × 3 知识点）

### 1. 五组消融

| 组 | 投影前幻觉率 | **投影后幻觉率** | 严口径幻觉率 | 适配准确率(决策口径) | 适配率(实测口径) | 通信稀疏度 | token 节省率 |
|---|---|---|---|---|---|---|---|
| A 基线（审核但不纠偏） | 5.78% | **5.78%** | 6.75% | 100.0% | 81.5% | 100.0% | 0.0% |
| B 协同 + 重生成纠偏 | 5.78% | **5.78%** | 6.75% | 100.0% | 81.5% | 100.0% | 0.0% |
| C 协同 + 知识约束投影 | 5.78% | **0.00%** | 6.75% | 100.0% | 81.5% | 100.0% | 0.0% |
| **D 本文方法（门控 + 投影）** | 5.78% | **0.00%** | 6.75% | 100.0% | 81.5% | **83.3%** | **31.0%** |
| E 消融：关闭学情诊断 | 5.17% | **0.00%** | 6.47% | 100.0% | **40.7%** | 61.1% | 68.7% |

三组对照各自回答一个问题：**C−B** 只差"纠偏方式"（重生成 vs 约束投影）；
**D−C** 只差"通信是否门控"；**E−D** 只差"有没有学情诊断"。
E 组把实测适配率打到 40.7%，说明**诊断是适配率的主要来源**，不是门控。

### 2. 门控阈值 τ 扫描

| τ | 0.0 | 0.2 | 0.3 | 0.5 | 0.8 | 1.0 |
|---|---|---|---|---|---|---|
| 通信稀疏度 | 83.3% | 83.3% | 83.3% | 61.1% | 38.9% | 0.0% |
| token 节省率 | 31.0% | 31.0% | 31.0% | 34.2% | 37.4% | 100.0% |
| 适配率(实测) | 81.5% | 81.5% | 81.5% | 81.5% | 81.5% | **29.6%** |

τ 的可用区间很宽（0～0.3 内无差别），但 **τ=1.0 时门控退化为"永不通信"，
实测适配率塌到 29.6%** —— 这给"门控阈值不能取到极端"提供了证据，而不是一句经验之谈。

### 3. 适配率：为什么要报**两个口径**，以及上界在哪

- **决策口径**：系统选的难度档，是否让**预测**正确率落进心流区间 [0.60, 0.80] → **100.0%**
- **实测口径**：学习者实际作答的正确率是否落进该区间 → 81.5%

两者都不该单独读：决策口径不受诊断精度影响（E 组关了诊断仍是 100%），
实测口径则完全受测量精度支配。`eval/oracle_ceiling.py` 做了**上界检验**：
把**真值掌握度**直接交给调度方（现实中拿不到）来选难度，实测口径仍然只有
**0.27～0.79（n=5）**，因为

- 每次投放只答 5 题 ⇒ 正确率被量化到 0/0.2/…/1.0，二项标准差 ≈ 0.2；
- 模拟器真值与诊断估计之间有 ±0.12 的确定性偏差。

**结论：离线环境不具备验证"实测口径 ≥85%"的能力，这个口径必须用真实学习者作答数据复测。**
本仓库把这个结论做成了可复现的表格（`out/eval/oracle_ceiling.json`），而不是写在局限里的一句话。

## 七、已知局限（**必须与上面的数字一起读**）

1. **离线后端（mock）的幻觉率衡量的是"机制有效性"，不是真实大模型的幻觉率。**
   mock 是确定性模板后端，内置 10 条真实领域误区作为 ground truth。其中"取证判定"这一步
   在离线夹具下由**条目级对账**（`engine/llm.py::MockLLM.judge` 第 1 条判据）代做，
   真实后端下由 LLM 的语义判定完成。**因此消融表衡量的是流水线能否抓住并修正冲突，
   不含判定器自身的识别能力。** 真实数值请用 `--backend openai` 复测。
2. **B 组（重生成）在离线后端下必然等于 A 组**：同一个确定性后端，同样的输入必得同样的输出，
   重生成不可能改变任何内容。要在真实后端上比较"重生成 vs 约束投影"，必须接真实模型。
3. **适配率是模拟口径**：离线演示没有真实学习者，作答由确定性模拟器 `LearnerSim` 产生，
   且模拟器与调度方共用同一张资源支撑系数表，因此该数值**高于**真实学习者群体能达到的水平。
   真实适配率需要真实作答数据；上界见 §四.3。
4. **幻觉率只统计"领域事实断言"**：操作性/流程性表述、疑问句题干、出处引用行不计入分母，
   且逐条记录、随审核明细一并输出（`non_domain` 字段）。这一豁免有三道兜底
   （绝对化词表 / 知识点标签 / 与证据重叠≥0.50）与一道反向约束（祈使句里出现程度/比较标记
   则取消豁免），细节见 `engine/claims.py::is_domain_claim` 的次序说明。
5. **投影逐条贪心**：每条声明单独投影，是全局最优的可计算近似；声明之间存在相互依赖的
   联合约束时需扩展为联合投影，本版本未实现。
6. **难度档的支撑系数是标定值**：`基础 1.45 / 进阶 1.10 / 挑战 0.80` 由心流区间
   反解得到（不是选的整数），依据与推导写在 `engine/orchestrator.py::DIFF_FACTOR` 注释里；
   换领域知识库或换学习者群体时需要重新标定。
