# 演示视频脚本（≤10 分钟）

**录制对象**：评审老师。**目标**：在 10 分钟内让人看明白三件事 ——
① 系统真的能跑（不是 PPT 工程）；② 多智能体协同决策是真的在跑（不是包装）；
③ 幻觉是被**机制**挡住的（有证据链，不是"我们小心了一点"）。

**总时长预算 9 分 30 秒**，留 30 秒余量。左侧为"做什么"，右侧为"说什么"（口播稿可直接念）。

## 录制前的一次性准备（不计入视频）

你在 **PowerShell** 里，下面三条照贴即可（`rmdir /s /q` 是 cmd 写法，PowerShell 会把 `/s`、`/q` 当成路径而报错，所以给了 PowerShell 版）：

```powershell

# 2) 先跑一次评测，让消融表格是当前代码的真实输出
python eval/run_eval.py

# 3) 打开两个窗口：一个浏览器（全屏），一个终端（字体调大，≥16pt）
```

> **录完之后补一条**：`python run.py --all-profiles` —— 第 1 步把三组画像的产物删了，而打包的 `07_测试数据` 要用到它们，跑这条就全回来（确定性输出，和删之前逐字节一致）。

> 建议：录屏分辨率 1920×1080，终端字号 16–18，浏览器缩放 110%。
> 画面里**不要出现**任何个人手机号、身份证号、未脱敏的问卷原件。

## 第 6 幕｜多智能体协同：门控通信与它的代价（7:00 – 8:00）

**动作**：打开 `out/L002/trace.jsonl`（默认设置下 L001 有 1 条被抑制、**L002 有 2 条，更好讲**），
用编辑器搜索 `"sent": false` —— 每条消息都带 `impact`（影响分）、`sent`、`reason` 三个字段，
抑制的理由形如 `影响分 0.000 ≤ τ=0.30`（影响分与阈值都打印出来，不是黑箱）；
再切到终端跑一次评测，展示消融表。

**口播**：
> "四个智能体之间不是每句话都传。系统用**因果影响**判断一条消息对下游决策值不值得发——
> 这来自多智能体强化学习里的 I2C 机制：只通信『会影响别人动作』的信息。
> 日志里每一条消息都记了影响分、是否发送、以及判定的理由，
> 所以『省通信』这件事本身也是可审计的。
>
> 但省通信有没有代价？我们做了消融。"

```bash
python eval/run_eval.py
```

> "五组对照，每组只改一个东西。C 和 B 只差纠偏方式；D 和 C 只差通信是否门控；
> E 和 D 只差有没有学情诊断。
> 结论有两句话值得说：
> **第一，门控把通信压到 83.3%、token 省 31%，而幻觉率和适配率一点没掉**——
> 省通信是免费的。
> **第二，把学情诊断关掉（E 组），适配率从 81.5% 掉到 40.7%**——
> 适配能力主要来自诊断，不是来自门控。这一条我们本来没料到，是消融跑出来的。"

## 第 7 幕｜诚实面对指标：两个适配率口径与上界检验（8:00 – 9:00）

**动作**：

```bash
python eval/oracle_ceiling.py
```

**口播**：
> "榜题要求适配准确率不低于 85%。我们报了两个口径：
> **决策口径 100%**——系统选的难度，是否让**预测**正确率落进心流区间；
> **实测口径 81.5%**——学习者实际作答的正确率是否落进区间。
>
> 这两个数都不能单独读，所以我做了上界检验：**把学习者的真值掌握度直接交给调度方**——
> 现实中不可能拿到的信息——再来测实测口径。结果每档 5 题时是 0.26 到 0.79，仍然远低于 85%。
> 原因有两个，都是测量问题而不是策略问题：每次只答 5 题，正确率被量化到 0.2 的粒度；
> 模拟器与诊断之间存在 ±0.12 的偏差。
>
> **所以我们的结论是：离线环境不具备验证这个指标的能力，必须用真实学习者作答数据复测。**
> 我们把这句话做成了可复现的表格，而不是写在局限里的一句话。
> 这也是我们对『刷指标』的态度：宁可报告一个解释得清楚的 81.5%，也不去凑一个 85%。"
