# 部署说明（Ph-MARL-Edu）

面向对象：**评审老师与需要在本机复现的部署者**。
按本文档操作，可在**无网络、无第三方依赖**的机器上完整跑通全流程；
接入真实大模型只需额外设置三个环境变量。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11、Linux、macOS 均可 | 开发与验证环境为 Windows 11 |
| Python | **3.8 及以上**（开发环境 3.10 / 3.11） | 只用标准库：`json`、`re`、`math`、`collections`、`http.server`、`urllib` |
| 第三方依赖 | **无** | 不需要 `pip install` 任何包；不需要 GPU；不需要数据库 |
| 磁盘 | < 20 MB（含知识库、题库、画像、评测产物） | |
| 网络 | 仅 `--backend openai` 时需要 | 离线 mock 后端完全不需要网络 |

> 自带实现以便零依赖：BM25 检索、分词、Levenshtein 编辑距离、HTML 报告、HTTP 界面、OpenAI 兼容协议调用。

---

## 二、部署步骤（离线，3 条命令）

```bash
# 1) 取得代码后，进入项目根目录（此后所有命令都在此目录执行）
cd Ph-MARL-Edu

# 2) 自检：跑单元测试，应显示 OK（171 条）
python -m unittest discover -s tests

# 3) 跑通一个画像的完整闭环（产物落在 out/L001/）
python run.py --profile L001
```

看到 `out/L001/report.html` 生成即可用浏览器打开；`out/L001/resources.md` 是交付给学习者的资源。

### 常用命令

```bash
python run.py --profile L001            # 单画像（默认 2 轮，每轮 2 个知识点）
python run.py --all-profiles            # 三组画像全跑
python run.py --profile L003 --rounds 3 --budget-kp 3 -v   # 更多轮次与细节输出
python run.py --ui --port 8017          # 浏览器界面（http://127.0.0.1:8017）
python run.py --profile L001 --full-comm      # 消融：关闭门控（全通信）
python run.py --profile L001 --gate-threshold 0.8   # 调整门控阈值 τ
python run.py --profile L001 --json     # 额外打印指标 JSON
python eval/run_eval.py                 # 五组消融 + τ 扫描
python eval/oracle_ceiling.py           # 适配率上界检验
python tools/build_kb.py                # 由源数据重建知识库与题库（确定性，可复现）
```

`python run.py --help` 可列出全部参数。

## 三、接入真实大模型（可选）

系统使用 **OpenAI 兼容接口**，任何提供该协议的服务均可（OpenAI、Azure OpenAI、通义/DeepSeek/智谱等兼容网关、本地 vLLM/Ollama 的兼容端口）。

```bash
# Windows PowerShell
$env:PHMARL_LLM_API_KEY="sk-xxxxxxxx"
$env:PHMARL_LLM_BASE_URL="https://api.openai.com/v1"     # 换成你的服务地址
$env:PHMARL_LLM_MODEL="gpt-4o-mini"                      # 换成你的模型名
python run.py --profile L001 --backend openai

# Linux / macOS / Git Bash
export PHMARL_LLM_API_KEY=sk-xxxxxxxx
export PHMARL_LLM_BASE_URL=https://api.openai.com/v1
export PHMARL_LLM_MODEL=gpt-4o-mini
python run.py --profile L001 --backend openai
```

要点：

- 未设置 `PHMARL_LLM_API_KEY` 时会**明确报错并提示**改用 `--backend mock`，不会静默降级；
- 真实后端下，报告与指标里会标注 `后端: openai`，与离线夹具结果区分开；
- **离线 mock 的幻觉率不能当作真实大模型的幻觉率**（见 README §七），对外汇报的真实数值必须用真实后端复测；
- 限流/超时：接口失败会回退为"该条声明证据不足"的保守处置，不会伪造结论。

## 四、复现评测结果

```bash
python -m unittest discover -s tests    # 期望：Ran 171 tests ... OK
python eval/run_eval.py                 # 五组消融 + τ 扫描
python eval/oracle_ceiling.py           # 适配率上界
```

产物：

| 路径 | 内容 |
|---|---|
| `out/eval/消融评测.md` | 消融报告（五组对照 + τ 扫描 + 逐画像明细 + 口径说明） |
| `out/eval/eval_results.json` | 同一份结果的机器可读版本 |
| `out/eval/oracle_ceiling.json` | 适配率上界检验的表格数据 |

全部为**确定性**输出：同一条命令、同一台机器，重复执行结果一致（后端为确定性 mock，
随机性由固定种子驱动）。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| 控制台打印中文报 `UnicodeEncodeError`（GBK 代码页） | Windows 旧代码页导致。设置 `PYTHONIOENCODING=utf-8` 后重跑；或 `chcp 65001` 切到 UTF-8 |
| PowerShell 里 `python run.py > log.txt` 得到 16 位宽的乱码文件 | PowerShell 5.1 默认 UTF-16LE 重定向。加 `PYTHONIOENCODING=utf-8`，或用 `| Out-File -Encoding utf8` |
| `python run.py --ui` 打开后页面空白 | 端口被占用或代理拦截，换端口：`--port 8020`，并确认访问的是 `127.0.0.1` 而非 `localhost` 代理地址 |
| 接真实后端报 401/404 | 检查 key、base url 是否包含 `/v1`、模型名是否与服务一致；先用 `--backend mock` 确认链路本身正常 |
| 想换领域知识库 | 改 `tools/build_kb.py` 的数据源并重跑；同时需重新标定难度支撑系数（`engine/orchestrator.py::DIFF_FACTOR`），依据见该处注释 |
